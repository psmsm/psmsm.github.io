🚀 EC2를 멈추지 않고 EBS 볼륨 용량 확장하기 (No Downtime)
AWS 클라우드 환경에서 운영 중인 서비스의 트래픽이나 데이터량이 급증했을 때, EC2 인스턴스를 호스팅하는 EBS(Elastic Block Store) 볼륨의 용량을 늘려야 하는 상황이 발생합니다. 다행히 AWS는 인스턴스를 정지하지 않고(No Downtime) 용량을 늘릴 수 있는 기능을 제공합니다.

하지만 AWS 콘솔에서 용량을 늘린 후, 인스턴스 내부에서 수동으로 진행해야 하는 후속 작업이 필수적입니다. 이 글에서는 인스턴스의 가용성을 유지하면서 EBS 볼륨의 용량을 확장하는 단계를 상세히 안내합니다.

1. 사전 준비 및 안전 조치
어떤 변경 작업이든 안전이 최우선입니다. 다음 두 가지 필수 단계를 먼저 진행합니다.

- 스냅샷 생성 (백업) 변경을 시작하기 전에 현재 EBS 볼륨의 스냅샷을 생성합니다. 이는 예상치 못한 문제가 발생했을 경우, 즉시 이전 상태로 복구(Rollback)할 수 있는 유일한 안전장치입니다.
- 현재 디스크 상태 확인 SSH로 인스턴스에 접속하여 현재 디스크, 파티션, 파일 시스템 상태를 확인합니다.

```
# 디스크 및 파티션 구조 확인
lsblk
# 파일 시스템 사용량 및 타입 확인
df -hT
```

2. AWS 콘솔/CLI를 통한 볼륨 크기 변경 (Backend 작업)
EC2 인스턴스를 실행 중인 상태 그대로 AWS 관리 콘솔에서 볼륨 크기를 수정합니다.
- EC2 대시보드에서 [볼륨] 메뉴로 이동합니다.
- 용량을 늘릴 대상 EBS 볼륨을 선택하고 [작업] $\rightarrow$ [볼륨 수정]을 클릭합니다.
- 원하는 새로운 용량(GiB)을 입력하고 [수정]을 클릭하여 작업을 시작합니다.
- 💡 볼륨 상태 모니터링볼륨 수정이 시작되면, 볼륨의 상태가 modifying $\rightarrow$ optimizing $\rightarrow$ completed 순서로 변경됩니다.
- optimizing 상태가 되는 즉시, 인스턴스 내부에서 파티션 및 파일 시스템 확장 작업을 시작할 수 있습니다.이 과정은 온라인(On-line)으로 진행되므로 서비스 중단은 발생하지 않습니다.

3. EC2 인스턴스 내부 작업 (Frontend 작업)
AWS에서 볼륨 크기를 80GB로 늘렸더라도, 운영체제(OS)는 여전히 이전 크기(예: 44GB)의 파티션만 인식하고 있습니다. 따라서 OS에게 "새로운 공간을 사용하라"고 알려주는 작업이 필요합니다.

3.1. 1단계: 파티션 크기 확장 (growpart)
growpart 명령어를 사용하여 파티션을 EBS 볼륨의 최대 크기까지 확장합니다. (Debian/Ubuntu 계열에서는 cloud-guest-utils 패키지에 포함되어 있습니다.)

✅ 명령어 구조:
```
# sudo growpart [장치 이름] [파티션 번호]
# 예시: /dev/nvme0n1 디스크의 1번 파티션 확장
sudo growpart /dev/nvme0n1 1
```

이 명령이 성공적으로 실행되면, 파티션이 디스크의 여유 공간을 모두 차지하게 됩니다. lsblk로 확인하면 파티션 크기가 커진 것을 볼 수 있습니다.

3.2. 2단계: 파일 시스템 크기 확장 (resize2fs 또는 xfs_growfs)
파티션을 늘렸어도, 데이터가 저장되는 파일 시스템 자체를 확장하지 않으면 용량을 사용할 수 없습니다.

확장 명령은 파일 시스템 유형에 따라 다릅니다. 이전에 확인한 df -hT 결과를 바탕으로 진행합니다.

📝 Case A: EXT4 파일 시스템인 경우 (가장 일반적)
```
# 장치 이름 사용
sudo resize2fs /dev/nvme0n1p1
```
이 명령어는 자동으로 파티션 끝까지 파일 시스템을 확장하며, 현재 마운트된 상태(On-line)에서도 안전하게 작동합니다.

📝 Case B: XFS 파일 시스템인 경우
```
# 마운트 포인트 사용 (예: 루트 디렉토리)
sudo xfs_growfs -d /
```

4. 최종 확인
모든 작업이 완료된 후, df -h 명령을 실행하여 루트 파일 시스템(/)의 Size가 AWS에서 늘린 80GB 크기로 정확히 반영되었는지 확인합니다.

```bash
df -hT
```

✅ 예상 출력: 파일 시스템의 Size가 변경된 크기(예: 78G)로 표시되며, Use%가 이전보다 낮아진 것을 확인할 수 있습니다.

EC2 인스턴스 용량 증가는 단순히 AWS 콘솔에서 숫자를 바꾸는 것을 넘어, 운영체제 내부에서 파티션 확장과 파일 시스템 확장을 수행하는 연속적인 과정입니다. 이 과정을 통해 서비스 중단 없이 안전하게 클라우드 리소스를 확장하고 안정적인 서비스 운영을 이어갈 수 있습니다.
